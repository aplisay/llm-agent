# Release 0.9.34 — Ultravox models, DTMF, failover

Three substantial features: agent failover, DTMF input via Ultravox, and a vendor-specific options framework starting with Ultravox transcription tuning.

## Highlights

### Agent failover
Agents can now declare a fallback agent and a failover phone number; on disconnect or startup failure the runtime cleanly hands the call over rather than dropping it. Ownership of the fallback agent is verified at deploy time. See [agent-failover.md](../../docs/agent-failover.md).

### DTMF input (Ultravox)
LiveKit agents using Ultravox can now receive DTMF input from the caller (e.g. "press 1 for…" flows). Implementation lives in the Ultravox realtime plugin ([realtime_model.ts](../../agents/livekit/plugins/ultravox/src/realtime/realtime_model.ts)).

### Vendor-specific options
New mechanism for passing model-vendor-specific options through the generic agent config, with Ultravox as the first user. See [ultravox-vendor-specific-options.md](../../docs/ultravox-vendor-specific-options.md) (note: superseded in 0.9.41 — this release shipped the original `ultravox-transcription-options.md`).

### SIP & telephony
- REFER now uses a `sip:` URI form for transfer targets, restoring compatibility with Xelion and Bicom PBXs.
- Added timeouts on room ID acquisition and the agent startup sequence so stuck calls fail fast instead of hanging.

### Reliability
- Better recovery and logging when an agent fails to start.
- Failsafe backward compatibility for older Ultravox model strings.
- `initialMessage` removed (was no longer functional).

### Tooling
- Removed unused `temp-livekit-agents` git submodule.
- Added an extra manual registration test fixture.
