# Release 0.9.41 — Pipeline agents

Major LiveKit agent refactor, SIP/telephony improvements, new voices/recognition APIs, some resilience improvements across infrastructure failure modes.

## Highlights

### Unified LiveKit agent stack

The LiveKit worker has been re-architected around a single runtime which covers both realtime and pipeline agents. [worker.ts](../agents/livekit/lib/worker.ts) shrinks from ~1,150 lines to ~100, with the heavy lifting moving into a new [voice-agent-runtime.ts](../agents/livekit/lib/voice-agent-runtime.ts), [voice-session-factory.ts](../agents/livekit/lib/voice-session-factory.ts), and a clean separation of [pipeline-inference-options.ts](../agents/livekit/lib/pipeline-inference-options.ts).

### Voices & recognition APIs

New per-model, per-locale endpoints: `GET /models/{modelName}/voices`, `GET /models/{modelName}/voices/{locale}`, and `GET /models/{modelName}/recognition/{locale}`. Voice selection is now scoped by model and locale, with a richer [model-voices](../lib/model-voices.js) catalogue. The legacy flat `/voices` shape is now formally deprecated — see [voices-deprecation.md](voices-deprecation.md).

### SIP telephony

- `X-Aplisay-Call-Id` is now propagated as a SIP header on outbound calls and on REFER-based transfers, making call correlation across PBXs straightforward.
- Improved registration-client handling for origination and REFER transfers ([transfer-handler.ts](../agents/livekit/lib/transfer-handler.ts), [telephony.ts](../agents/livekit/lib/telephony.ts)).
- Better cleanup of bridged calls.
- Phone numbers and registrations now record a `callReceived` column so operators can see if a number has ever had a call routed to the platform to confirm successful new number deployment.

### Agent behaviour

- **Uninterruptible greetings** — new option to prevent caller barge-in during the opening message ([uninterruptible-greetings.md](uninterruptible-greetings.md)).
- **`options.greeting`** has a clear, documented definition.
- **Ultravox** vendor-specific options expanded ([ultravox-vendor-specific-options.md](ultravox-vendor-specific-options.md))
- **Ultravox** deprecated modelname sticking plaster: the `livekit:ultravox/ultravox-70b` model alias is restored for backward compatibility.

### Resilience

- LiveKit worker now recovers more cleanly from some transient failures.
- The API service restarts on loss of database connectivity rather than recovering and running degraded with live streaming transcript updates not being propagated.
- Several frequently occurring and recoverable Livekit API errors have been demoted from error to info-level logging to reduce noise.

### Permissions & scope

Unified permission implementation scoping across the API and LiveKit agent ([lib/scope.js](../lib/scope.js), [agents/livekit/lib/scope.js](../agents/livekit/lib/scope.js)) with better comprehensive test coverage ([tests/scope.test.mjs](../tests/scope.test.mjs)).

### API additions

- Call recordings are now exposed on `GET /calls`.
- New `/agent-db` phone-endpoint routes for managing numbers tied to agents.

### Docs & tooling

- New docs: [number lifecycle](number-lifecycle-adding-a-number.md), [LiveKit pipeline API implications](livekit-pipeline-api-implications.md), [uninterruptible greetings](uninterruptible-greetings.md), [voices deprecation](voices-deprecation.md), [Ultravox vendor options](ultravox-vendor-specific-options.md). The originate-API doc has been rewritten.
- New operator scripts: [analyse-abandoned-calls.js](../tools/analyse-abandoned-calls.js) and [analyze-call-logs.js](../tools/analyze-call-logs.js).

### Bug fixes

- Hotfix for [#111](https://github.com/aplisay/llm-agent/issues/111).
- Stray debug `console.log` removed; minor log formatting fix.

## Upgrade notes

- Callers still using the flat `/voices` endpoint should migrate to the model/locale-scoped endpoints — see [voices-deprecation.md](voices-deprecation.md).
