# Release 0.9.37 — Recording, concurrency limits, number management

Introduces production call recording, per-tenant concurrency limits, a number-management API, and tool-call chaining via metadata.

## Highlights

### Call recording (RecorderIO)
End-to-end RecorderIO-based call recording on the LiveKit stack:

- New recording capture pipeline ([call-recording.ts](../../agents/livekit/lib/call-recording.ts), [worker.ts](../../agents/livekit/lib/worker.ts)).
- Recordings are persisted alongside an invocation log ([api/paths/calls/{callId}/recording.js](../../api/paths/calls/{callId}/recording.js), [api/paths/calls/{callId}/invocation-log.js](../../api/paths/calls/{callId}/invocation-log.js)).
- Recording keys are stored encrypted in the database ([lib/database.js](../../lib/database.js)).
- Recordings are preserved across session lifecycle events that previously risked losing them.
- See [call-recording.md](../../docs/call-recording.md) and [plan-recording-rest-and-options.md](../../docs/plan-recording-rest-and-options.md).

### Agent concurrency limits
Per-instance, per-user, and per-organisation concurrency limits, with calls cleanly rejected (and a call row preserved for audit) when limits are exceeded:

- New SQL-backed concurrency tracking ([lib/concurrency/agent-concurrency-limits-sql.js](../../lib/concurrency/agent-concurrency-limits-sql.js)).
- Concurrency state consolidated into a single table.
- WebRTC handler is included in the limit accounting.
- See [agent-concurrency-limits.md](../../docs/agent-concurrency-limits.md).

### Number management API
- New phone-numbers / numbering tab API surface ([api/paths/phone-endpoints.js](../../api/paths/phone-endpoints.js), [api/paths/phone-endpoints/{identifier}.js](../../api/paths/phone-endpoints/{identifier}.js)).
- `provisioned` flag added to phone numbers, distinguishing provisioned vs merely configured numbers.
- Trunk ID disambiguation: where the SBC presents multiple plausible trunk IDs, the runtime now resolves to the target number rather than guessing ([api/paths/agent-db/phone-endpoints.js](../../api/paths/agent-db/phone-endpoints.js)).
- Updated [phone-endpoints-api.md](../../docs/phone-endpoints-api.md).

### Tool-call chaining via metadata
Tool calls can now chain by passing metadata between calls, with a `redact` flag to keep sensitive payload parts confidential from the LLM.

- Implementation: [lib/function-handler.js](../../lib/function-handler.js), [lib/handlers/toolsCalls-metadata-capability.js](../../lib/handlers/toolsCalls-metadata-capability.js).
- `hasDynamicMetadata` is checked against agent definitions before enabling the capability.
- See [tool-call-chaining-metadata-priming.md](../../docs/tool-call-chaining-metadata-priming.md).

### Diagnostics
- Richer Ultravox call diagnostics at info level ([realtime_model.ts](../../agents/livekit/plugins/ultravox/src/realtime/realtime_model.ts)).
- Warm-transfer call IDs are now correlated across legs in [tools/ultravox-correlate.js](../../tools/ultravox-correlate.js); a standalone Ultravox call-ID tracking tool was also added.
- Transfer transcripts handed back to the parent agent are Markdown-quoted.
- The "announce yourself" user turn that conflicted with some prompts has been removed.

### Misc
- `agentId` and `instanceId` were dropped from `InvocationLog` (they were causing deploy-time DB upgrade problems).
- Added a media timeout and session-close optimisation to free worker resources faster.
- Org-scoped users can now retrieve call logs ([middleware/auth.js](../../middleware/auth.js), [api/paths/agents.js](../../api/paths/agents.js)).
- Fix for an Ultravox issue with path variables in tool URLs.
- Jambonz and Groq test suites dropped from the main CI run (both were brittle / deprecated).
