# Release 0.9.39 — API fixes & listener security

Merged via [PR #110](https://github.com/aplisay/llm-agent/pull/110) (from `next`). Small, security-flavoured release that closes an authorisation gap on listener deletion, hardens the internal `agent-db` namespace, and adds a dashboard-friendly listener listing endpoint.

## Security

### Listener deletion is now scoped to the caller
`DELETE /api/listener/{listenerId}` and `DELETE /api/agents/{agentId}/listen/{listenerId}` previously matched only on `listenerId`, so any authenticated tenant could delete any listener instance by ID.

This didn't have any major security implications as the listenerId is a UUID with buge entropy so not guessable or brute forceable but could conceivably have causes issues is clients leaked am instanceId to an attacker.

Both endpoints now require the listener to belong to the authenticated caller's user or organisation and return `404` when it does not.

- [api/paths/listener/{listenerId}.js](../../api/paths/listener/{listenerId}.js)
- [api/paths/agents/{agentId}/listen/{listenerId}.js](../../api/paths/agents/{agentId}/listen/{listenerId}.js)

### `agent-db` is now hard-gated to the shared token
`/api/agent-db/*` is intended for internal service-to-service calls only. Previously a request that failed the shared-token check would fall through to Firebase / AuthKey tenant auth, meaning a tenant credential could in principle reach internal endpoints. The auth middleware now explicitly rejects any tenant-authenticated request to `/api/agent-db` with a `403 Forbidden`.

- [middleware/auth.js](../../middleware/auth.js)

## API additions

### `GET /api/listener`
New flat listing of active listener instances, scoped to the caller's user/org and joined to their parent agent. Intended for dashboards. Each item includes:

- `agentId`, `agentName`
- `kind` — one of `phone`, `registration`, `webrtc`
- `phoneNumber`, `registrationId`, `registrationName`
- `createdAt`

Supports `?agentId=` for filtering to a single agent.

- [api/paths/listener.js](../../api/paths/listener.js) (renamed from `listeners.js`)

### Registration `options` exposed on phone endpoints
`GET /api/phone-endpoints/{identifier}` now returns the registration's `options` payload alongside the existing fields, so clients no longer need a separate fetch to see the configured options for a registration-backed endpoint.

- [api/paths/phone-endpoints/{identifier}.js](../../api/paths/phone-endpoints/{identifier}.js)

## Upgrade notes
- Anyone calling the listener-delete endpoints with cross-tenant IDs will now see `404` instead of a successful delete. This is a behaviour change but the previous behaviour was a bug.
- Internal services must use `SHARED_API_TOKEN` (via the `x-shared-token` header) for any `/api/agent-db/*` call; tenant credentials will be rejected.
