# Release 0.9.40 — Phone-endpoints agent visibility hotfix

A single-commit hotfix release on top of 0.9.39, addressing [#111](https://github.com/aplisay/llm-agent/issues/111).

## Bug fix
`GET /api/phone-endpoints` was returning numbers without their associated agent name or `agentId`, even when an agent was deployed against the number. The root cause was that the Sequelize query only selected `Instance.id`, so the subsequent visibility check (which compares `Instance.userId` / `Instance.organisationId` against the caller) treated every row as cross-org and stripped the `Instance` — and with it the linked `Agent` — from the response.

## Changes
- [api/paths/phone-endpoints.js](../../api/paths/phone-endpoints.js)
  - Pull `userId` and `organisationId` onto the `Instance` include so the org/user visibility check has the data it needs.
  - Extract the visibility filter into a small `stripPhoneNumberInstancesForUser` helper and apply it to both query branches.
  - The unfiltered `PhoneNumber.findAll` branch now also includes `Instance` → `Agent` and surfaces `inUse`, `agentId`, and `agentName` on each returned number.
- Test coverage extended in [tests/phone-endpoints-comprehensive.test.mjs](../../tests/phone-endpoints-comprehensive.test.mjs), [tests/agent-phone-number-workflow.test.mjs](../../tests/agent-phone-number-workflow.test.mjs), and [tests/listener-join-originate.test.mjs](../../tests/listener-join-originate.test.mjs) to lock in the agent-visibility behaviour.

## Upgrade notes
- API consumers can now rely on `agentId`, `agentName`, and `inUse` being populated on `GET /api/phone-endpoints` whenever the caller has visibility of the linked instance.
- No schema changes; no client-side migration required.
