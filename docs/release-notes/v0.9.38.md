# Release 0.9.38 — Large-tenant `/agents` fix and frontend-enabling additions

Merged via [PR #109](https://github.com/aplisay/llm-agent/pull/109). Small, targeted release: fixes a query that was failing for very large tenants on `GET /api/agents`, plugs an information leak on orphaned phone numbers, and lands a handful of API additions that unblock the Aplisay frontend.

## Highlights

### Fix: `GET /api/agents` for very large tenants
The agents-list query was rewritten to be coherent end-to-end (single query path, fewer ad-hoc joins), eliminating the failure mode that was hitting tenants with many agents. Implementation in [api/paths/agents.js](../../api/paths/agents.js).

### Security: don't leak agent names on orphaned phone numbers
`GET /api/phone-endpoints` no longer returns the parent agent name when a phone number has been orphaned (the linked instance no longer exists or is not visible to the caller) ([api/paths/phone-endpoints.js](../../api/paths/phone-endpoints.js)).

### Frontend-enabling API additions
- New `room-key` endpoint for listeners ([api/paths/listener/{listenerId}/room-key.js](../../api/paths/listener/{listenerId}/room-key.js)) — supports the WebRTC join flow used by the frontend.
- Expanded `agents.js` and the `agent-db/phone-endpoints.js` surface with the fields the frontend needs to render correctly.
- New flat `listeners.js` listing endpoint (later renamed to `listener.js` and security-scoped in 0.9.39).
- API doc updated to reflect the additions ([api/api-doc.yaml](../../api/api-doc.yaml)).
